# Отчет о сравнении проектов SculptSP (JS) и SculptSP Native (C++)

В данном отчете представлен подробный анализ текущего состояния миграции проекта **SculptSP** с JavaScript на C++ (Native), проведено сравнение их архитектур и технологических стеков, а также выделен список функционала, который все еще остается непортированным или портирован лишь частично.

---

## 1. Сравнение технологических стеков

| Характеристика | SculptSP (JavaScript / Legacy) | SculptSP Native (C++ / Текущий) |
| :--- | :--- | :--- |
| **Язык разработки** | JavaScript (ES6) + C++ (компилируемый в WASM) | Чистый C++17 |
| **Графическое API** | WebGL 2.0 (через браузер) | OpenGL ES 3.0 (через ANGLE / нативные драйверы) |
| **Оконная система / События** | Браузерный DOM (Canvas, Mouse/Touch events) | SDL2 (кроссплатформенная обработка окон и ввода) |
| **Интерфейс пользователя (UI)** | Кастомная CSS/HTML библиотека (`yagui`) | Dear ImGui (нативный рендеринг интерфейса во вьюпорте) |
| **Управление памятью** | Garbage Collector (JS) + ручное управление в куче WASM | Полностью ручное и безопасное управление (RAII, умные указатели) |
| **Сборщик / Пакетный менеджер** | npm/pnpm/yarn, Vite, Electron/Tauri (для десктопа) | CMake + Ninja (нативная компиляция без зависимостей Node.js) |

---

## 2. Что уже успешно перенесено (Feature Parity)

В ходе этапов миграции в C++ версии были полностью реализованы следующие ключевые возможности:
1. **Базовый и продвинутый скульптурный движок**:
   - Перенесены все основные кисти **Группы А**: *Flatten, Smooth, Inflate, Pinch, Crease, Move, Drag, Elastic, V-Tool*.
   - Перенесены продвинутые кисти **Группы B и C**: *Masking, Painting, Twist, Local Scale, Clay, Clay Buildup, Dam Standard, Square Brush, Visibility*.
   - Нативная поддержка динамической топологии (Dyntopo) и воксельного ремешинга (оптимизированного по памяти с использованием разреженных структур).
2. **Система ввода и управления**:
   - Выделенный `CameraController` с поддержкой Orbit (вращение), Pan (панорамирование) и Zoom (зум).
   - Единый `HotkeyDispatcher` с поддержкой зажатия модификаторов (`Shift` для Smooth, `Ctrl` для Masking, `Alt` для инверсии знака кисти).
   - Устранение задержки курсора за счет прямого опроса мыши перед рендером и отрисовки точки курсора в экранном пространстве.
   - Поддержка графических планшетов (Stylus Pressure) под Windows через Pointer API.
3. **Рендеринг и визуальные эффекты**:
   - Шейдеры Matcap (9 предустановок) и PBR-материалы с IBL/SPH освещением.
   - Сглаживание краев (FXAA) и отрисовка сетки (Wireframe), контуров выделения (Contour Outlines).
   - Рендеринг референсных изображений (Reference Images) в качестве 2D-оверлея или 3D-плоскости.
   - Навигационный куб в углу экрана (Navigation Cube/Gizmo) для быстрого выравнивания камеры.
4. **Файловая система**:
   - Из импорта/экспорта поддерживаются форматы **OBJ, STL, PLY, GLTF/GLB**, а также нативный формат сцены **SGL**.
   - Нативная панель импорта/экспорта в GUI.

## 3. Что еще НЕ портировано в C++ Native

Ниже приведен детальный список возможностей из JavaScript-версии, которые отсутствуют в нативном C++ приложении или реализованы только в виде заготовок (stubs).

### А. Непортированные инструменты и кисти (Tools)
1. **Инструмент трансформации меша (`Transform` / `BRUSH_TRANSFORM`)**:
   - **В JS**: Позволяет перемещать, вращать и масштабировать выбранный меш целиком (или его выделенную маской часть) с помощью интерактивного 3-осевого гизмо (стрелки, кольца и кубы трансформации).
   - **В C++**: Инструмент отсутствует. Навигационный куб вьюпорта реализован, но полноценного 3D-трансформатора для самого меша нет.
2. **Создание мешей из сфер (`Z-Spheres` / `BRUSH_ZSPHERE`)**:
   - **В JS**: Инструмент создания скелета из связанных сфер различного радиуса (`ZSphereTool.js`) с возможностью последующей генерации адаптивной сетки (Adaptive Skin).
   - **В C++**: Функционал полностью отсутствует (нет класса `ZSphereRig`, логики генерации кожи и интерфейса для добавления/редактирования сфер).
3. **Кисть локальной сетки (`Topology` / `BRUSH_TOPOLOGY`)**:
   - **В JS**: Кисть локального изменения плотности сетки. При проведении ею по мешу происходит локальное триангулирование/разбиение (subdivision) или децимирование (decimation) вершин на основе заданного радиуса без изменения формы меша (сдвиг вершин равен нулю).
   - **В C++**: Данная кисть не добавлена в список доступных инструментов и не имеет реализации логики локального триангулирования.
4. **Деформация по кривой (`Curve Deform` / `BRUSH_CURVE_DEFORM`)**:
   - **В JS**: Позволяет деформировать и сгибать меш вдоль интерактивно нарисованной сплайновой кривой (`CurveDeformTool.js`).
   - **В C++**: Функционал полностью отсутствует.
5. **Линейка и Делитель отрезков (`Measure` / `Divider`)**:
   - **В JS**: Инструменты измерения расстояния на поверхности модели с выводом 2D-аннотаций и деления отрезков на равные части (`MeasureTool.js`, `DividerTool.js`).
   - **В C++**: Существуют лишь пустые заглушки для импорта/экспорта этих данных из файлов `.sgl` в модулях `ImportSGL.cpp` и `ExportSGL.cpp`. Визуализаторы (`MeasureRenderer`/`DividerRenderer`) и логика построения отрезков отсутствуют.

### Б. Реализовано в коде движка, но не подключено к GUI/Input
1. **Градиентное размытие маски (`Mask Gradient Blur` / `BRUSH_MASK_GRADIENT_BLUR`)**:
   - **В движке C++**: Математика градиентной маски (`applyGradientMask` и `blurMask`) уже написана в файлах `SculptEngine.cpp` и `SculptEngine.h`.
   - **Проблема**: Этот инструмент не зарегистрирован в перечислении `BrushType` (`common/Enums.h`), не выведен в панель кистей `GuiManager` и не обрабатывается в `SculptManager` и `HotkeyDispatcher`. Пользователь не может его активировать.

### В. Архитектурные системы и оптимизации
1. **Система мультиразрешения (Multiresolution LOD / `StateMultiresolution.js`)**:
   - **В JS**: Полноценная поддержка уровней детализации (LOD). Пользователь может разбивать меш на более высокие уровни (Subdivide), восстанавливать нижние уровни (Reconstruct Lower), переключаться между ними слайдером во время скульптинга и удалять ненужные уровни истории (Delete Higher/Lower).
   - **В C++**: Архитектура `Scene` и `Mesh` поддерживает только один активный уровень сетки. Переключение LOD и алгоритмы Catmull-Clark / Loop подразделения сетки отсутствуют. Доступен только деструктивный воксельный ремешинг.
2. **Дельта-сжатие истории (Delta-compressed Undo/Redo)**:
   - **В JS**: Шаги Undo/Redo сохраняют только измененные вершины и грани для экономии оперативной памяти.
   - **В C++**: Реализовано сохранение полной копии состояния меша (`MeshState`) в стек истории. При работе со сложными моделями (более 1 млн полигонов) это может приводить к избыточному потреблению памяти.

## 4. Рекомендации по дальнейшей миграции

Для достижения 100%-го паритета с JS-версией рекомендуется разбить оставшиеся задачи на следующие этапы:

1. **Этап 1 (Подключение готового кода)**:
   - Добавить `BRUSH_MASK_GRADIENT_BLUR` в `BrushType`, интегрировать его в интерфейс настроек маскирования и подключить к обработчику жестов мыши.
2. **Этап 2 (Инструменты измерения и деформации)**:
   - Реализовать `MeasureTool` и `DividerTool` вместе с их рендерингом (отрисовка линий и текстовых подписей с размером во вьюпорте поверх меша).
   - Перенести гизмо трансформации меша (`TransformTool`), используя сторонние библиотеки гизмо для ImGui (например, `ImGuizmo`) или написав простой нативный рендер осей.
3. **Этап 3 (Multiresolution & LOD)**:
   - Реализовать хранение списка уровней LOD в классе `Mesh` и методы перехода между уровнями с интерполяцией координат.
4. **Этап 4 (Z-Spheres & Curve Deform)**:
   - Реализовать структуру рига Z-сфер, операции добавления/связывания нод во вьюпорте и алгоритм генерации меша по сферам.
